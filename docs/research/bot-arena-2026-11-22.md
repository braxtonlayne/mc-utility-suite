**Retreat/disengage.** mineflayer-pvp documents no retreat logic (only `stop()`); I could not read its API.md, so a retreat behaviour is [UNVERIFIED], but the README implies it just chases and attacks. The nxg package's README lists distance management but no flee/stop-on-low-HP condition; check `src/swordpvp/API.md` after install [UNVERIFIED]. If any retreat or auto-stop does exist, patch it out or drive the fight from our own loop (re-issue `attack(target)` every tick until death).

**Gear.** Mineflayer bots cannot give themselves items. Use server commands (`give`, `item replace entity <bot> armor.head with ...`, `/clear`) from the harness over RCON or the server console. The bot must then equip: the nxg README example includes a shield-equip helper; armour equips via `bot.equip(item, 'head'|'torso'|'legs'|'feet')`. Prefer `item replace` so armour is worn immediately.

**Headless run.** Node script: `mineflayer.createBot({host:'127.0.0.1', port:25565, username:'ArenaBot', version:'1.21.1', auth:'offline'})`, load pathfinder + pvp plugin, then `attack()` on spawn. No window needed. Whether `version:'1.21.1'` is accepted by minecraft-data in this mineflayer release is [UNVERIFIED]; 1.21 and 1.21.1 share protocol 767 in my knowledge, so 1.21 data should work.

**Honest strength assessment.** The Mineflayer options are the only genuinely open-source ones, and even the best (nxg) is a modest bot: no armour/gapple management, and its target version badge stops at 1.19. A stack of "beat the strongest open-source bot" claims should therefore say "strongest *open-source* bot found, patched". PvB is probably stronger and 1.21.1-native but closed-licence; it is a fair optional second opponent if the owner is fine with running closed freeware locally (licence ARR does not forbid private use, but check its terms).

## 2. Server choice

Recommendation: **Paper 1.21.1**, offline mode (`online-mode=false`), `enforce-secure-profile=false`.
- Mineflayer joins any vanilla-protocol server; Paper is vanilla-compatible, so offline mode works for the bot and the owner's client.
- The NeoForge client should join a non-modded server. A NeoForge 21.1 client joining vanilla/Paper normally works, but our mod's own network channels must be optional/client-only [UNVERIFIED, test once].
- Grim is a Paper/Spigot/Folia/Fabric plugin ([GrimAC](https://modrinth.com/plugin/grimac)), so plain vanilla cannot run it. Paper therefore covers Grim, Citizens, and RCON. A Fabric server would only be needed for PvB (1.21.1 Fabric) or Grim's Fabric build; do not mix.
- Paper download: https://papermc.io/downloads/paper (the v2 API returned HTTP 410, so use the website or v3 API). File size about 50 MB [UNVERIFIED].

**Scripting rounds (RCON on, `enable-rcon=true`, local-only password):**
- Per round: `kill` both, `clear` both, `tp` to fixed spawn points facing each other, `effect clear`, `give`/`item replace` the kit, `effect give @a minecraft:resistance 3 255 true` as a 3-second countdown or use `gamemode adventure` until the go signal, `heal` via `effect give instant_health`, saturation top-up. `/gamerule keepInventory false`, `/gamerule doImmediateRespawn true`, `/difficulty peaceful` off (use `normal`) or natural regeneration will skew results (`/gamerule naturalRegeneration false` is the clean option).
- Kits: (1) fists, no armour; (2) mixed (e.g. our iron/diamond mix vs theirs); (3) opponent netherite plus enchantments, shield, gapples vs our leather/stone or iron.
- Scoring: parse `logs/latest.log` for death lines (`<victim> was slain by <killer>`, `... was killed ...`); timestamps give time-to-kill (log time minus the go signal). Vanilla scoreboard objectives add damage: `scoreboard objectives add dmg minecraft.custom:minecraft.damage_dealt` and `scoreboard objectives add kills playerKillCount` (the `playerKillCount` criterion is vanilla). Read with `scoreboard players get`. Also log our client's own combat stats if the mod exposes them.
- Timeout per round (e.g. 90 s) = draw/loss for us. Pass criterion: 8 of 10 wins in each hard scenario, with a fixed list of spawn positions and seeds recorded.
- To keep the bot from stopping: harness loop re-sends `attack()` to the bot process whenever the bot goes idle and nobody has died.

## 3. Anticheats (1.21.1, open source preferred)

**GrimAC** (best match): [GrimAnticheat/Grim](https://github.com/GrimAnticheat/Grim), Modrinth [modrinth.com/plugin/grimac](https://modrinth.com/plugin/grimac) (about 834K downloads, updated about 15 hours before I read it, so very active). Licence GPL-3.0 (Modrinth: GPL-3.0-or-later). README says it supports 1.8 to 26.3; the Modrinth game-version list includes 1.21.x. Platforms: Bukkit, Fabric, Folia, Paper, Purpur, Spigot; needs Java 17+. Offline mode: not confirmed [UNVERIFIED], but Grim only needs player packets so I expect it to work.
- Movement: a simulation/prediction engine reproducing vanilla movement (knockback, cobwebs, bubble columns, riding). This is the best check for our "legit movement" claim. Flags show as Simulation/Prediction violations.
- Combat: Grim also has reach, hitbox, rotation/aim (e.g. aim-modulo and invalid-rotation style checks), attack-direction, and click/autoclicker-type checks. I know these from prior knowledge; the wiki Checks page would not load, so exact check names are [UNVERIFIED]. Read the Checks wiki page before approving thresholds.
- Reading flags: alerts go to the console and to ops with the alerts toggle (`/grim alerts`); `/grim verbose` shows every violation; `/grim history <player>` and `/grim profile <player>` show past violations and client info. Violations are written to the server log and (if enabled) a history database. Command names are from memory [UNVERIFIED]; confirm on the wiki. For the harness, parse `latest.log` for the Grim alert lines (default format contains the check name and `VL:`).
- Grim cares about simulation exactness, so an automation mod that sends correct inputs through real key states should be clean; rotation snapping and perfectly regular click timing are what usually get flagged. Our 450 deg/s cap and smoothing are in line with that.

**Others:** [LightningGrim](https://modrinth.com/plugin/lightning-grim-anticheat) (GPL-3.0 fork of Grim tuned for 1.21.1; unnecessary if official Grim works). Vulcan, Matrix, Intave, Spartan: paid, excluded. Open-source non-Grim alternatives (NoCheatPlus, Spartan-free, etc.) are mostly outdated for 1.21.1 and not evaluated [UNVERIFIED].

**Important testing caveat:** run the anticheat with the bot present too (Mineflayer bots can themselves flag Grim; exclude the bot by name with `/grim` exempt/bypass permission `grim.exempt` [UNVERIFIED permission name] or only count alerts for our player).

## 4. Recommended setup

- **Server:** Paper 1.21.1 offline mode, RCON enabled, localhost-only, view-distance 6, a flat void-free arena platform with barrier walls (built by `/fill` commands at round 0).
- **Opponent:** `@nxg-org/mineflayer-custom-pvp` on mineflayer 4.39.x via a small Node 20+ script ("ArenaBot"), configured for crits (hop), intelligent strafe, w-tap, shield/axe, `cps` about 10-12, all retreat or stop paths removed or bypassed, with a watchdog that re-attacks. Fallback if nxg refuses 1.21.1: use mineflayer-pvp plus a few hundred lines of our own crit/w-tap/strafe code. Optional second opponent: PvB (Fabric 1.21.1) on a separate Fabric server, only if the owner accepts the ARR licence.
- **Anticheat:** official GrimAC plugin on the Paper server, default config, alerts to log.
- **Harness (Python or Node, lives in `tools/arena/` of the repo, outside the mod jar):** start Paper, wait for "Done", start ArenaBot, wait for our client to join (the owner launches `runClient`, or an automation hook starts the combat assistant on a chat command), then per round: reset via RCON, apply the kit, go signal, watch the log for the death line, record winner, TTK, damage dealt via scoreboard, Grim alerts count and check names. Write results to JSON/CSV, summarize wins per scenario (pass: >= 8/10 in each).
- **Effort:** about 1 to 2 days: half a day for server, Grim, bot to connect; half a day for the bot config and retreat-proofing (the risky part, nxg is untested on 1.21.1); half a day for the round harness and log parsing; extra time to run the 3 scenarios times 10 rounds and tune. Running real fights needs the game client open on the owner's machine (GPU/laptop on), so schedule it outside the pre-work window.

## First results (2026-11-22 afternoon)

Setup: Paper 1.21.1 build 133 (offline, 127.0.0.1:25570), `./gradlew runArena` client with the Combat Assistant
on Proactive (players), duel mode, everything else default. Opponent: `@nxg-org/mineflayer-custom-pvp` 1.7.16 with
legit settings (hop crits with reaction timing, smoothed legit rotation, legit shield, full-swing, 12 CPS), which
never disengages. Natural regeneration on; both start with instant health and full saturation. 90 s round limit.

### Anticheat (GrimAC 2.3.75, everything default)
- 23 rounds (2 fists, 3 + 10 mixed, 10 stacked) with Grim on: **zero flags on our client.**
- The bot was flagged all the time: Simulation 69 alert lines (each line is a batch of violations), NoSlow 52,
  AntiKB 14, Reach 8, PositionBreakA 4, Post 2. Grim's setbacks crawl the bot at about 0.5 block/s and cancel its
  hits, so results with Grim on are anticheat checks, not fair fights.
- Grim-on mixed: 8/10, 0 losses (the bot was handicapped).

### Fair benchmark (Grim removed from plugins/, now in server/plugins-off/)
| Setup | Ours | Bot | Timeouts | Pass (8/10) |
|---|---|---|---|---|
| fists (even) | 9 | 0 | 1 | yes |
| mixed (bot: full iron + shield, ours: iron sword + mixed iron/chain/leather) | 8 | 1 | 1 | yes |
| stacked (bot: full diamond, Sharpness II, shield; ours: stone sword, full leather) | 0 | 4 | 6 | **no** |

Stacked pattern: our health bottoms out at about 4 every round. The duel reset then retreats to regenerate while
the bot regenerates as well, so most rounds time out, and the bot takes the ones where the reset is caught.

### Fixes this run turned up
- Duel mode no longer resets when a reset cannot heal (no healing item, hunger under 18). Before this, an
  out-geared client at 4 HP kited for the rest of the round (commit 7ac5172).
- Harness: mineflayer's state goes stale after deaths and respawns (its swings stopped landing at 1-3 blocks, and
  rounds became no-damage timeouts), so arena.js now connects a fresh bot every round. It also samples both
  health values and the distance every 2 s over RCON. A `PartialReadError` (ArmorTrimMaterial in a slot component)
  is logged at bot join; it does not stop the bot.

### Open
