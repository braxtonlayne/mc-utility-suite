# STEM visual language: sci-fi HUD overhaul (design, 2026-11-22)

Status: **design only, no code changed.** Nothing here was built, compiled or seen in a game client.
API names marked *(verify)* are from memory of 1.21.1 / NeoForge 21.1 and must be checked against the mapped
sources by the first build item that touches them.

Trigger: the owner's hands-on test on 2026-11-22 ("graphically it's a 2010 client ... I want it to truly look like
an advanced client, like really advanced"), chosen direction **sci-fi HUD / STEM**: thin-line cyan holographic HUD,
corner brackets, scanline and glow touches, a neural-implant feel after *Upgrade* (2018). Same test: combat and the
other features should improve generally, and control hand-back after a parkour assist was too abrupt. This doc covers
the visual layer and the part of those two complaints that is a *visibility* problem (sections 8.6 to 8.8); the
movement and combat logic changes belong to their own designs.

## 1. What makes the current build read as "2010"

Seen in the screenshots and the code, most damaging first:

1. **The HUD has no shared style at all.** `ModuleListHud` is black 56 % boxes with shadowed vanilla text. `TabGui`
   is flat grey rectangles with a solid `#38BDF8` selection block. `TargetHud` and `FightCoachHud` draw their own
   `g.fill` + shadowed strings with private colour constants. Status messages land in the vanilla action bar
   ("Auto-Fish stopped: no rod (0 catches)") and in chat ("[Suite] Light Levels on").
2. **World overlays use raw `RenderType.lines()`** in saturated primaries (pure green box, yellow grid, red arcs,
   magenta verticals in `modules-smoke.png`). Fixed-width aliased GL lines with no falloff are the single most
   "old client" signal on screen.
3. **In a fight nothing on screen says the mod is working.** `combat-engaged.png` shows a vanilla crosshair and a
   6 px bar; there is no target lock, no threat direction, no sense of a system tracking anything.
4. **The menu is competent but generic "dark dashboard"**: opaque `#141416` window, rounded cards, iOS-style
   toggles, pill buttons. It matches the three-column reference layout but has no identity, no depth, and the only
   motion is a 120 ms open fade and the toggle knob.
5. **The pixel font** carries a lot of the retro feel on its own, especially at 0.75 scale (`smallText`) where it
   turns to mush.
6. **Colour is doing too many jobs.** Category chips are loud solid red/amber blocks (`COMBAT`, `TOOL`), the
   autopilot bar goes solid green, and accent blue is used for selection, sliders, headings and toggles alike.

The layout (three columns, pinned autopilot bar, search, legit level) is approved and **stays**. This is a
re-skin plus a motion system plus a HUD rebuild, not a re-layout.

## 2. Principles

1. **One light source.** Everything is a thin line of light on dark glass. Cyan means "the system". Other hues are
   reserved for meaning (section 3.1), never decoration.
2. **Lines, not boxes.** Panels are defined by hairlines and corner brackets; fills are translucent and only as
   opaque as text contrast requires.
3. **Motion explains state.** Every transition answers "what just changed": something locked on, something took
   control, something gave it back. No ambient animation on the in-game HUD while nothing is happening.
4. **Readable first.** Body text is never drawn over the world without a plate. Glow never sits behind text.
   Minimum text contrast 7:1 against its plate.
5. **Rule 6 is absolute.** Idle means zero draw calls. Clean-Screen means zero draw calls (the opt-in Clean badge
   stays the single exception). Effects have an intensity setting and an off switch (section 9).
6. **Modules publish state, the Shell draws.** No module outside the Shell holds a colour constant, a font or a
   `g.fill` call once adoption is done (section 6).

## 3. Visual language

### 3.1 Palette tokens

All colours live in one class (`HoloTheme`, replacing the colour half of `UiTheme`). Tokens are `int` ARGB; the
accent family is derived once from a configurable hue (default cyan) when the setting changes, never per frame.

| Token | Default | Use |
|---|---|---|
| `VOID` | `#05080B` | deepest backing, menu backdrop tint (at 55 %) |
| `GLASS` | `#0A1218` @ 78 % | panel fill (menu window, cards) |
| `GLASS_HUD` | `#070D12` @ 62 % | HUD plates behind text |
| `GLASS_RAISED` | `#10202A` @ 86 % | hover, active rows, popovers, tooltips |
| `FIELD` | `#060B0F` @ 90 % | inputs, slider tracks, insets |
| `LINE_FAINT` | accent @ 16 % | panel edges, dividers, grid |
| `LINE` | accent @ 38 % | default borders, inactive brackets |
| `LINE_STRONG` | accent @ 100 % | brackets, active borders, selection |
| `ACCENT` | `#3DE8FF` | the system: selection, ON state, sliders, STEM |
| `ACCENT_DEEP` | `#0E5C6E` | ON track fill, pressed |
| `ACCENT_GLOW` | accent @ 22 % | outer glow layers only |
| `ON_ACCENT` | `#021318` | text on a solid accent fill |
| `TEXT` | `#E6FBFF` | primary text |
| `TEXT_SECONDARY` | `#9CC7D1` | labels, descriptions |
| `TEXT_MUTED` | `#5C7F8A` | captions, disabled, units |
| `TEXT_FAINT` | `#35505A` | watermark readouts, inactive chips |
| `SYNC` | `#3DFFB4` | a reflex or job is *acting right now* |
| `WARN` | `#FFB547` | caution, waiting, less-legit settings |
| `DANGER` | `#FF4D5E` | Stop-All, lethal threat, errors |
| `ALLY` | `#6EA8FF` | roster players |
| `MANUAL` | `#FFFFFF` | the user's own share of control (section 8.6) |

Category hues survive only as a 2 px indicator bar and a micro label tint, never as a filled chip:
Jobs `#FFC857`, World `#5CE0A0`, Travel `#5BB8FF`, Combat `#FF6B7A`, Tools `#B69CFF`. `SuiteMenuScreen.Tab.chipColor()`
and `ModuleListHud.colorOf` read these tokens.

Accent presets: Cyan (default), Ice `#A8E9FF`, Green `#4DFFA0`, Amber `#FFB547`, Magenta `#FF5CD0`, plus a hue
slider. Status hues do not move with the accent; if the accent hue comes within 25 degrees of a status hue the status
token is drawn with its glyph (section 3.5) so colour is never the only signal.

### 3.2 Surfaces and the bracket frame

The single shape of the system is the **bracket frame**:

- fill `GLASS`, 1 px `LINE_FAINT` edge all round;
- four L-shaped corner brackets in `LINE_STRONG`, 1 px thick, arm length `clamp(min(w, h) * 0.18, 4, 10)` px,
  sitting on the edge (not outside it);
- optional 4 px 45 degree chamfer on the top-left and bottom-right corners for *hero* surfaces (menu window, hero card,
  toasts). The chamfer is a stair-step of 1 px row fills from a precomputed inset table, the same trick
  `UiRenderUtils.INSETS` uses for round corners;
- no drop shadows. Depth comes from a 3-layer outer glow in `ACCENT_GLOW` (10 %, 6 %, 3 %, each 1 px further out) on
  the *one* focused surface, and from the blurred world behind the menu.

Three emphasis levels, used consistently:

| Level | Edge | Brackets | Glow | Used by |
|---|---|---|---|---|
| quiet | `LINE_FAINT` | none | none | list rows, cards inside the content column, HUD plates |
| framed | `LINE_FAINT` | `LINE` | none | cards, popovers, toasts, target tag |
| hero | `LINE` | `LINE_STRONG` | yes | menu window, active job card, takeover state, primary target |

Corner radius is **0 or chamfer**. Rounded pills and round toggle knobs go away; the only round things are
reticle arcs and progress rings.

### 3.3 Line weights

1 px hairline for all structure. 2 px only for: selection indicator bars, slider fill, progress fills, the active
edge of a toast. In-world lines are soft ribbons 1.5 px core + falloff (section 5.3), never raw GL lines unless
effects are off.

### 3.4 Glow and scanlines

- **Glow** is additive-looking falloff around *lines*, never a blurred copy of a panel. Three sources only: the hero
  outer glow above, the soft ribbon falloff, and a 9-slice soft sprite behind ON indicators (toggle bar, active dot).
- **Scanlines**: 1 px lines every 3 px at 4 % `ACCENT` inside hero surfaces only, drawn as one tiled quad from the
  kit atlas. A **sweep** (a 24 px tall vertical gradient band at 5 %) travels down the menu window once on open
  and then every 8 s while the menu stays open. No scanlines or sweeps on the in-game HUD, except for the 600 ms
  engage and takeover transitions.
- **Flicker** is used exactly once: the 2-frame brightness dip when a surface first appears. Never periodic.

### 3.5 Glyphs

Status is always colour **plus** shape, drawn from 7x7 px glyphs in the kit atlas: `●` idle/armed, `▶` running,
`◆` acting, `‖` waiting, `▲` warning, `✕` failed/stopped, `✓` done. Chevrons, the search loupe, the settings cog,
back arrow and scroll thumb come from the same atlas. Vanilla item icons stay for jobs and tabs (they are useful and
recognisable) but sit inside a bracketed 18 px cell.

## 4. Typography

### 4.1 Options weighed

| Option | Look | Build cost | Runtime cost | Licence | Verdict |
|---|---|---|---|---|---|
| A. Vanilla bitmap font | pixelated, the main "retro" tell; mush at 0.75 scale | none | none | none | keep as fallback and as an explicit setting |
| B. Bundled TTF through the vanilla font pipeline (a font JSON with a `ttf` provider; glyphs rasterised by the game's FreeType path, cached in vanilla glyph atlases) | crisp at 1.0 scale with `oversample`, real weights, tabular digits from a mono face | low: assets + one thin wrapper; all existing code keeps passing a `Font` | same as vanilla text (batched, atlas-cached) | font file needs its own licence (below) | **recommended** |
| C. Own MSDF atlas + shader + text layout | sharp at any scale, cheap glow/outline in the shader | high: atlas generation, a core shader, own layout, kerning, width measurement, fallback glyphs, every `Font` call site rewritten | one extra shader bind; fine | atlas output is ours; generator tools (msdf-atlas-gen, MIT) run offline and are not shipped | defer; revisit only if B looks soft at GUI scale 1 or 4 |

Why B: the menu never scales text (`UiTheme`: "always drawn at 1.0 scale"), so MSDF's main advantage is unused,
and B needs no change to the ~9000 lines that already take a `Font` parameter.

### 4.2 How B plugs in

- Assets: `assets/utilitysuite/font/ui.json`, `ui_micro.json`, `mono.json`, each one `ttf` provider
  (`file`, `size`, `oversample`, `shift`) *(verify provider fields for 1.21.1)*.
- `HoloFont` builds **suite `Font` instances** that resolve the default font id to ours, so plain `String` drawing
  works unchanged: `new Font(id -> base.apply(DEFAULT.equals(id) ? SUITE_ID : id), false)` where `base` is the
  font-set lookup of `mc.font` *(verify the `Font` constructor and field name)*. Reaching that lookup needs one
  accessor (an access-transformer line, or failing that a one-method accessor mixin listed under `client`); this is
  the only non-event hook in the whole design and it is read-only.
- Three instances: `ui` (body 9 px line), `micro` (7 px caps labels, replacing the 0.75 pose scale in
  `SuiteMenuScreen.smallText`), `mono` (numerals: coordinates, HP, distances, slider values, so digits do not jitter).
- Setting `visual.font`: `Suite` (default) / `Vanilla`. `Vanilla` hands out `mc.font` for all three. If the suite
  font fails to load, or the game's "Force Unicode Font" is on, fall back to vanilla and say so once in the log.
- All widths are already measured through the `Font` passed in, so layout follows automatically. Every
  hard-coded `8`/`10` px line-height assumption (`HudPill`, `ModuleListHud` rows, `TabGui.ROW_H`) moves to
  `HoloTheme.lineHeight(role)`.

### 4.3 Font licence

The project rule (MIT/Apache/BSD only) is written for code. Fonts are mostly SIL OFL 1.1, which allows bundling in
closed software but requires shipping the copyright and licence text and forbids reusing a Reserved Font Name on a
modified (for example subset) file. **Owner decision needed**; two routes:

1. Stay inside the written rule: an Apache-2.0 family (the classic Roboto Condensed + Roboto Mono releases are
   Apache 2.0 from memory, *verify on the upstream repo before download*). Clean, neutral, slightly less "sci-fi".
2. Allow OFL for font files only: a techier face (candidates from memory, all to be verified: Rajdhani, Chakra
   Petch, Oxanium, Exo 2 for UI; JetBrains Mono or Share Tech Mono for numerals).

Either way: ship the files **unmodified**, put the licence text in `assets/utilitysuite/font/LICENSE-<family>.txt`,
list them in a top-level `THIRD-PARTY-NOTICES.md`. Cost: roughly 100 to 300 KB per unmodified TTF, three files.
Recommendation: route 2 with Rajdhani (UI, micro) + JetBrains Mono (numerals) if the owner accepts OFL; otherwise
route 1.

Type scale: window title `ui` caps `TEXT`; card title `ui` `TEXT`; body `ui` `TEXT_SECONDARY`; section and field
captions `micro` caps `TEXT_MUTED`; every number `mono`.

## 5. Rendering architecture

### 5.1 Contracts (`com.utilitysuite.core.api.visual`, engine-agnostic like the rest of `core.api`)

`core.api` imports no Minecraft classes today; the new contracts keep that, so they stay unit-testable with fakes.

| Contract | Purpose |
|---|---|
| `IVisuals` (via `Services.visuals()` / `visualsOrNull()`) | entry point: `hud()`, `notices()`, `marks()`, `effects()` |
| `IHudHost` | modules register a `HudElement` (id, `HudSlot`, priority, `boolean wantsDraw()`, `measure(IHoloCanvas)`, `draw(IHoloCanvas, x, y, alpha)`). The host owns placement, stacking, fades, Clean-Screen and F1/F3 gating |
| `IHoloCanvas` | 2D drawing in tokens, primitives only: `plate`, `frame(level)`, `brackets`, `hLine/vLine`, `ribbon`, `arc`, `bar`, `glyph`, `text(role, String, x, y, token)`, `number(role, int, ...)`, `item(registryId, ...)`, `width(role, String)` |
| `IHoloWorld` | 3D drawing, camera-relative floats: `ribbon`, `polyline(float[], count)`, `ring`, `boxEdges`, `groundMark`, with a token and an alpha |
| `IWorldMarks` | fixed slot table (16) of things to put a reticle on: entity id or packed pos, `MarkKind` (`PRIMARY_TARGET`, `THREAT`, `ALLY`, `OBJECTIVE`, `LANDING`), plus primitive readouts (health 0..1, charge 0..1, distance, a short label). Modules write slots on tick; the Shell draws |
| `INoticeBoard` | `post(NoticeKind, String title, String detail)`; ring of 8 preallocated slots |
| `EffectLevel` | `OFF`, `SUBTLE`, `FULL` (section 9) |

`Services` is orchestrator-owned: adding `visuals()` is one small, separate, first commit.

### 5.2 2D kit (`com.utilitysuite.ui.holo`)

- `HoloTheme`: tokens, metrics, line heights. `UiTheme` keeps its metric constants and its colour constants become
  aliases during migration, then are deleted.
- `HoloKit`: implements `IHoloCanvas` over `GuiGraphics`. Rectangles and brackets are plain `g.fill` quads (already
  batched by vanilla into the GUI buffer). Everything that is not axis-aligned goes through **one soft-ribbon
  primitive**: a quad strip whose U coordinate samples a 1x16 falloff texel row, so a line, an arc or a ring is
  anti-aliased by texture filtering and gets its glow for free. Vertices are written straight to the
  `VertexConsumer` with the current pose matrix; arcs use a 256-entry sin/cos table.
- One atlas, `assets/utilitysuite/textures/gui/holo.png` (256x256): ribbon falloff rows (hard, soft, glow), 9-slice
  soft glow, scanline tile, the 7x7 glyph set. Authored by us from a small generator script checked into `tools/`,
  so there is no third-party art.
- Two render types: `holo_gui` (position-tex-colour, translucent, no depth, for ribbons and sprites) and vanilla GUI
  fills. A HUD frame therefore costs at most three state changes: fills, ribbons, text.
- **No `pushPose` on HUD paths.** In 1.21.1 each push allocates a `PoseStack.Pose` *(verify)*; HUD code offsets
  coordinates itself. The menu may push (it already does for scale) but not per widget per frame.
- `FrameClock`: sampled once per frame by the first Shell layer; exposes `dtSeconds` (clamped to 0.05) and `nowMs`.
- `AnimStore`: open-addressing `long -> float[4]` table (value, velocity, target, lastTouchedFrame) keyed by a stable
  widget key hash. It survives `Panel.rebuild()` (which throws the node tree away) and replaces
  `ToggleSwitch.RECENT` (a `HashMap<String, long[]>`). Entries untouched for 2 s are reclaimed in place.

### 5.3 3D kit and the screen projector

- `HoloWorldKit` implements `IHoloWorld`: camera-facing soft ribbons (width proportional to distance so they hold
  roughly 1.5 px on screen), the same falloff texture, a `holo_world` render type (translucent, depth-tested, no
  depth write, no cull) and a `holo_world_through` variant without the depth test for modes that are already
  see-through today (X-ray outlines, waypoints). Drawn in `RenderLevelStageEvent`, one batch per pass, ended once.
- At `EffectLevel.OFF`, and when a shader pack is active, it falls back to today's `RenderType.lines()` /
  `WorldRenderKit.linesNoDepth()` path with the new palette. Custom render types under Iris/Oculus are the main
  compatibility risk; the fallback is a setting (`visual.world_lines`: `Auto` / `Ribbons` / `Plain`), with `Auto`
  choosing `Plain` when a shader pack is detected *(detection by reflection on the Iris API, no hard dependency)*.
- `ScreenProjector`: in the last `RenderLevelStageEvent` stage it copies the model-view and projection matrices into
  two reused `Matrix4f`, then projects each occupied `IWorldMarks` slot (interpolated with the partial tick) into
  preallocated `float[]` screen rectangles + a visible flag. The reticle layer (GUI) only reads those arrays.
  **Reticles are screen-space**: constant line weight, crisp text, glow, and no Sodium or shader-pack interaction.
  Open risk to check in game: view bobbing and FOV effects must line up with the projection the event exposes.

### 5.4 Hot-path rules (performance mandate)

- Render callbacks allocate nothing in the steady state: no `String.format`, no boxing, no lambdas, no `Vec3`,
  no `Component` creation. Strings are rebuilt on change (as `HudStatusLine` does now); integers draw through a
  cached table like `WorldRenderKit.number`.
- Every Shell layer starts with the same early-out chain: disabled -> Clean-Screen -> `hideGui` -> nothing wants to
  draw -> return, before touching the font or the buffers.
- Budgets (asserted in tests through a recording `IHoloCanvas`): in-game HUD at most 600 quads and 40 text runs in
  the worst realistic frame (module list 32 rows + reticle + 3 toasts + status line + authority bar); world kit at
  most 512 ribbon segments per frame, extra segments dropped farthest first.
- Sodium-safe: nothing touches chunk meshes; all drawing is immediate-mode GUI or level-stage buffers.

## 6. Adoption: how every module ends up in one style

Three patterns, in order of preference:

1. **Publish, don't draw.** Target, threat, ally, landing and objective markers go into `IWorldMarks`. Messages go
   to `INoticeBoard`. The module deletes its renderer. (TargetHud, The Read's cooldown, FightCoach's danger arrow,
   action-bar and chat status messages.)
2. **Draw through the canvas.** A module with its own HUD element registers a `HudElement` and draws only with
   `IHoloCanvas` tokens; the host places it in a slot and fades it. (FightCoach pips, InfoStrip, Minimap frame,
   status line.)
3. **Draw through the world kit.** Geometry that is genuinely 3D uses `IHoloWorld`. (Ghost Line, movement overlay,
   hazard outlines, X-ray highlights, schematic ghost edges, waypoint beacons.)

Enforcement, added to the static checks in `CLAUDE.md` once migration is done:

```
grep -rnE 'g\.fill\(|drawString\(|RenderType\.lines\(\)|0x[0-9A-Fa-f]{8}' src/main/java \
  | grep -vE '/ui/holo/|/ui/kit/|/world/render/'
```

must be empty apart from an allow-list file of reviewed exceptions (map tile colours in the minimap, block tints in
the schematic ghost). A unit test runs the same scan so it fails in `./gradlew test`.

HUD slots (the host stacks elements in a slot by priority and animates reflow when one appears or leaves):
`TOP_LEFT` (info strip, Tab-GUI), `TOP_CENTER` (status line, stopped badge), `TOP_RIGHT` (module list),
`CROSSHAIR` (coach pips, authority indicator), `RIGHT_MID` (target tag when it has no room next to the reticle),
`BOTTOM_RIGHT` (toasts), `FREE` (minimap, user-placed). The existing `SuiteHud.topUsed` hand-off disappears.

## 7. Motion system

All motion is frame-time driven (`FrameClock.dtSeconds`), never tick-driven, and uses two curves only:

- **settle** (critically damped follow): `v += (target - v) * (1 - exp(-dt / tau))`. For positions, sizes, list
  reflow, hover. `tau` 45 ms (fast), 80 ms (normal), 140 ms (slow).
- **snap** (ease-out-back, 8 % overshoot) on a fixed duration. Only for brackets locking on and toggles landing.

| Transition | Curve | Time | What moves |
|---|---|---|---|
| hover in / out | settle fast | ~90 ms | edge `LINE_FAINT` -> `LINE`, brackets extend 2 px, fill +6 % |
| press | instant + settle | 60 ms | 1-frame bright flash, then settle |
| toggle | snap | 140 ms | indicator bar slides; ON gains the soft glow sprite |
| slider drag | settle fast | follows | fill and value text; thumb is a 2 px vertical bar with a bracket |
| category switch | settle normal | 140 ms | content cross-fades and slides 6 px; the sidebar selection bar travels |
| card expand / collapse | settle normal | 160 ms | height, with a scissor; chevron rotates by swapping glyph |
| list reflow (search, module list HUD) | settle normal | 160 ms | each row's y follows its target; entering rows fade + slide 10 px |
| menu open (boot, first time per session) | sequence | 900 ms | section 8.2 |
| menu open (after that) | sequence | 220 ms | section 8.2 |
| menu close | settle fast | 110 ms | fade + 4 px contract; input returns to the game on the first frame |
| toast in / out | settle | 160 / 220 ms | slide 14 px from the right + fade |
| reticle lock-on | snap | 180 ms | brackets contract from 2.2x to fit |
| autopilot engage / release | sequence | 600 / 400 ms | section 8.5 |

Rules: input is live from the first frame of every animation (clicks are never eaten by a transition). **Stop-All,
manual-input preemption and danger states never wait on an animation.** With `visual.motion = Off` every `tau` and
duration is zero and sequences jump to their end state.

## 8. Components

### 8.1 Menu chrome (`SuiteMenuScreen`)

- Backdrop: the vanilla menu blur (`renderBlurredBackground` *(verify)*; it respects the player's accessibility
  blur setting) + `VOID` at 55 % + a soft vignette. This alone removes most of the "flat overlay" feel.
- Window: hero bracket frame, `GLASS`, chamfered, scanlines, sweep on open. Columns are separated by `LINE_FAINT`
  hairlines, not different fills (`SIDEBAR`, `LIST_BG`, `WINDOW` collapse into one glass surface).
- Title bar: `UTILITY SUITE` in `ui` caps with a 2 px accent bar; version and profile as bracketed `micro` readouts;
  the goal field becomes a `FIELD` inset with a `▶` prompt glyph and a blinking caret only while focused. `CLEAN` is
  a standard toggle. **Stop all stays a solid `DANGER` control** (the one filled button in the system) with a
  `✕` glyph.
- Sidebar: rows are quiet; the selected row gets a travelling 2 px accent bar on the left, `GLASS_RAISED`, and
  brackets. Counts are `mono` in `TEXT_MUTED`. Footer status ("Automation on / Idle") uses the status glyph set.
- Module list column: category chips (`COMBAT`, `TOOL`) become a 2 px hue bar + nothing; the row's right edge has
  the state glyph (`●` armed in `ACCENT`, dim dot when off, `◆` in `SYNC` when the module holds a lease right now).
  Search filtering reflows rows with the list transition.
- Content cards: framed level. Card title row with the master toggle at the right; a hairline under it. Section
  headings (`Proactive`, `Tactics`) become `micro` caps in `ACCENT` with a hairline running to the card edge.
- Tooltip: `GLASS_RAISED` plate, framed, appears after 350 ms with a 90 ms fade, never covers the control it explains
  (it currently overlaps the `Proactive targets` row in `menu-combat.png`): prefer below-right, flip when clipped.
- Scrollbar: 2 px `LINE` thumb on a `LINE_FAINT` rail, brightens on hover.

### 8.2 Boot and sync sequence

First open in a session (900 ms, skippable by any input, never blocks input):

| t (ms) | Event |
|---|---|
| 0 - 120 | a 1 px accent line grows from the window centre to full width |
| 120 - 300 | the line splits and the frame unfolds vertically; brackets snap in at the corners (snap curve); 2-frame flicker |
| 300 - 520 | sidebar, list, content fade and slide in, 40 ms apart; labels reveal left to right behind a bright 1 px caret (a scissor reveal: no per-frame strings) |
| 520 - 900 | top-right `micro` readout counts up: `SYNC 100 % - 49 MODULES - LINK OK`, then fades to `TEXT_FAINT`; one sweep |

Later opens: 220 ms (frame unfold 0 - 110, content fade 60 - 220), no readout. The readout numbers are real
(module count from the registry, profile id), drawn from the cached number table.

### 8.3 Controls (kit widgets)

| Widget | New form |
|---|---|
| `ToggleSwitch` | 22x10 bracketed rail; OFF = `LINE` outline with a dim bar at the left; ON = `ACCENT_DEEP` fill, bright 8 px bar at the right with the glow sprite. Less-legit toggles use `WARN` for the ON bar |
| `PillButton` | rectangular, framed; primary = `ACCENT` outline + accent text + faint fill; danger = `DANGER` outline, solid only for Stop all |
| segmented (`CycleSelector`, legit level, engagement) | one frame, hairline separators, the selected segment has a sliding `ACCENT` underline + `GLASS_RAISED`; no filled blue block |
| `ModernSlider` | 2 px rail `LINE_FAINT`, 2 px fill `ACCENT`, thumb = 2x10 bar with mini brackets; value in `mono`; tick marks at defaults |
| `StyledTextField` | `FIELD` inset, bottom edge `LINE` -> `LINE_STRONG` on focus |
| `ChipNode` / reflex chips | text + hairline frame; lit = `ACCENT` text and frame, unlit = `TEXT_FAINT`; acting = `SYNC` with `◆` |
| `CardNode`, `GoalHeroCard` | framed / hero bracket frames; hero card progress is a 2 px bar with a `mono` percentage |
| `CollapsibleSection`, `ListRowNode`, `LabelNode`, `BoxNode` | quiet level, tokens only |

### 8.4 Autopilot bar becomes the STEM strip (`AutopilotBar`, `ReflexChips`)

Same position and behaviour (approved 2026-11-21). OFF: quiet strip, `AUTOPILOT` in `TEXT_MUTED`, chips in
`TEXT_FAINT`. ON: no solid green; instead a 2 px `ACCENT` bar at the left, the label in `ACCENT`, a 24 px wide
"pulse" trace (three-segment polyline ribbon that advances only while the menu is open), lit chips in `ACCENT`,
and the chip of a reflex that acted in the last 10 s marked `◆` in `SYNC`. Turning it on plays the frame-unfold on
the strip (300 ms) and a one-shot sweep across the chips.

### 8.5 Autopilot on the HUD

- **Engage** (autopilot switched on in game): a 1 px accent line pulses outward from the crosshair to 60 px each
  side and fades (600 ms), a toast `AUTOPILOT ONLINE`. Then nothing: armed is not a reason to draw (rule 6). An
  optional "armed" marker (four dim 8 px screen-corner brackets) exists as a setting, **default off**.
- **Takeover** (a reflex acts): screen-corner brackets snap in at 12 px inset in `SYNC`, the status line shows
  `◆ STEM - FALL CLUTCH` (hero level), the authority indicator appears (8.6). All of it is driven by the existing
  `IAutopilot.activeReflex()` edge that `SuiteHud` already watches.
- **Release**: brackets and line fade over 400 ms; zero draw calls after that.

### 8.6 Control authority indicator (new; answers "it gives control back instantly")

Part of the fix for the fence/wall walk-off is logic (a hold-through window and a blended hand-back, owned by the
movement control-modes design). The other part is that today **the user cannot see who is steering or when control
returns**. The indicator makes that explicit:

- A 40 px wide, 3 px tall split bar 14 px under the crosshair: the left share in `MANUAL` white, the right share in
  `ACCENT` (assist) or `SYNC` (full reflex). The split is the current authority 0..1.
- During a hand-back window the assist share **drains** right to left over exactly the remaining hold time, so the
  user sees control coming back instead of feeling it drop. A `micro` label under it names the reason: `LANDING`,
  `EDGE HOLD`, `CORNER`.
- Appears only while authority > 0 or a hand-back is in progress; fades 200 ms after. Never in Clean-Screen.
- Data needed from the control-modes design (a `core.api` view, primitives only): authority per `ControlChannel`
  0..1, hand-back ticks remaining and total, a reason enum. If that design ships several modes (nudge, semi-STEM,
  full STEM), the menu shows them as one segmented control on the Movement Assist card and the STEM strip.

### 8.7 Status line, badges, info strip (`SuiteHud`, `HudPill`, `HudStatusLine`, `InfoStrip`)

- Status line: framed plate (`GLASS_HUD`), brackets, status glyph, bracketed item cell, progress in `mono`, step
  text in `TEXT_SECONDARY`, and a 1 px progress hairline along the bottom edge. Text changes cross-fade (120 ms)
  instead of popping. Still one line, still rebuilt only on `JobChanged`.
- `Automation stopped`: `DANGER` framed plate with `✕`; appears with the snap curve so it is noticed. Clean badge:
  quiet plate.
- Info strip: quiet plate, `micro` caps captions over `mono` values (`XYZ`, `BIOME`, `TPS`, `PING`), hairline
  separators.

### 8.8 Combat on the HUD (`TargetHud`, `ReadRingModule`, `FightCoachHud`)

This is where "combat could improve" is partly a display problem: the systems built in the last volleys (reads,
combo keeper, arena field, threat model) are invisible in `combat-engaged.png`.

- **Primary target reticle** (screen-space, from `IWorldMarks`): four corner brackets hugging the projected box
  (minimum 14 px), lock-on contraction on acquire. Left side: a segmented vertical health bar (`ACCENT` -> `WARN` ->
  `DANGER` by fraction). Bottom: The Read's attack-cooldown as an arc that fills, with a chevron on the side of the
  predicted strafe (this replaces the separate world-space ring; the ring remains available as a style option).
  A leader line runs to a framed tag: name, HP in `mono`, distance, and one state word from the tactic layer
  (`HOLD GAP`, `COMBO`, `BAIT`, `RETREAT`).
- **Line of sight is respected.** The reticle marks only what the combat module already tracks under its own legit
  rules. When LOS is lost the brackets go dashed and dim, and vanish when the module drops the target. The HUD adds
  no information the module did not already have.
- **Threats**: on screen, a thin diamond bracket in `WARN` (projectile) or `DANGER` (blast, lethal). Off screen,
  an edge chevron on an ellipse around the crosshair pointing at the threat, with distance. Replaces the coach's
  text arrow.
- **Coach pips**: the 6 px bar becomes a segmented cooldown arc under the crosshair; `CRIT` and `BACK OFF` cues are
  glyph + `micro` word, colour-coded, in the `CROSSHAIR` slot.
- **Allies**: small `ALLY` corner ticks, no tag unless looked at.
- Pop counter, target line: tokens and ribbons.

### 8.9 Enabled-module list (`ModuleListHud`)

Keeps the classic idea the owner asked for (list of what is on, right edge, opt-in), rebuilt:

- Rows right-aligned, `ui` font, no text shadow; each row a plate that fades out to the left (one horizontal
  gradient quad) with a 2 px category-hue bar on the screen edge.
- Header row `◆ STEM` in `ACCENT` while the autopilot is on, with the pulse trace.
- **Motion**: a module turning on slides in from the right 10 px and fades (160 ms) with a one-shot bright bar; one
  turning off fades and its neighbours close the gap with the list-reflow curve. Per-row animation state lives in
  preallocated arrays indexed by the module's registry index, so identity survives re-sorting.
- **Live state**: a module that holds a control lease right now shows `◆` in `SYNC` and its bar brightens. This
  comes from the existing `LeaseGranted` / `LeaseEnded` events, so no polling.
- Sort setting: longest first (default, classic), by category, or by recent activity. The once-a-second enabled
  mask check stays as is.

### 8.10 Toasts (`INoticeBoard`, new `NoticeLayer`)

- Bottom-right stack, max 3 visible, framed + chamfered plates, 2 px kind-coloured left edge, glyph, title in `ui`,
  optional one-line detail in `TEXT_SECONDARY`, and a 1 px lifetime hairline that drains.
- Kinds: `INFO` (accent), `DONE` (`SYNC`), `WARN`, `ERROR` (`DANGER`). Life 2.5 s (4 s for `WARN`/`ERROR`).
  Identical titles within 2 s merge into one toast with an `x3` counter. More than 3 queued: oldest `INFO` dropped.
- Clean-Screen: dropped, not queued (they still reach the Timeline). Posting allocates (it is an event, not a hot
  path); drawing does not.
- Migrate: `Panel.toast` (the in-menu toasts used by all five tabs), the dot-command chat feedback
  ("[Suite] Light Levels on"), and every action-bar status message ("Auto-Fish stopped: no rod").

### 8.11 Tab-GUI, Timeline, Goal console, minimap, previews

- `TabGui`: two framed plates; selection is a bracketed row with the travelling accent bar instead of a solid block;
  ON state as the glyph. Opening the module column uses the frame-unfold (120 ms). Navigation logic untouched.
- `TimelineScreen`: same window chrome as the menu; events on a vertical hairline spine with glyph nodes coloured by
  kind; timestamps in `mono`.
- `GoalConsole`: the prompt field style from the title bar; parse preview as a framed card; errors as an inline
  `DANGER` hairline + message.
- `MinimapHud` / `MinimapLayoutScreen`: bracket frame, hairline range ring and cardinal ticks, the player as an
  accent chevron; map tile colours are unchanged (allow-listed).
- `ShulkerPreview`: framed plate with a hairline slot grid.

### 8.12 World geometry (`GhostLineModule`, `MovementAssist` overlay, `TerrainAssist`, `WorldOverlaysModule`, `GhostPreviewRenderer`, waypoints)

- Ghost Line: a soft accent ribbon whose alpha fades with distance along the path, dashes that advance toward the
  landing (phase from `FrameClock`, no allocation), and a bracketed ground mark at the predicted landing: `ACCENT`
  when the jump is good, `WARN` when marginal, `DANGER` when it will miss. This gives the parkour assist a visible
  "I have this jump" signal.
- Movement overlay (the green box in `parkour-3-gap-airborne.png`): the landing block gets top-face corner brackets
  only, not a full box; the takeoff edge gets a 2 px accent tick when the assist intends to jump there.
- Hazards: `DANGER` hairline on the hazardous faces + a slow 1 Hz alpha breathe, only within 8 blocks.
- X-ray / ore outlines, chunk borders, light overlay, radar: keep their information colours (ore identity matters)
  but drawn as ribbons at 60 % with corner emphasis; the yellow full-grid light overlay becomes corner ticks per
  block (about a quarter of the segments it draws today).
- Schematic ghost: accent bracket edges for "to place", `WARN` for "wrong block", `SYNC` flash when placed.
- Waypoints: a thin vertical ribbon beam + a screen-space bracket tag through `IWorldMarks` (`OBJECTIVE`).

## 9. Settings (one "Appearance" card under Tools, stored in the profile like every other module)

| Key | Values | Default | Effect |
|---|---|---|---|
| `visual.effects` | Off / Subtle / Full | Full | Off: no glow, scanlines, sweeps, ribbons (plain lines), flat plates. Subtle: glow and ribbons, no scanlines/sweeps/flicker |
